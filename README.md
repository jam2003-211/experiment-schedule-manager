# 実験スケジュール管理

ブラウザだけで使える、個人向けの実験進行管理アプリです。工程を上から実施する順に並べ、完成希望日時から逆算するか、開始日時から順方向に予定を作成します。データはブラウザの `localStorage` に保存され、サーバーには送信されません。

## 主な機能

- 実験ストックの登録、検索、状態管理
- 工程テンプレートの作成、複製、上下並べ替え
- 1つの計画への複数テンプレート追加（同一テンプレートの再適用確認を含む）
- 表示順をそのまま実施順とする直列スケジュール
- 作業時間と、日・時間・分で入力する待機時間
- 暦時間待機と作業可能時間待機
- 曜日別の作業可能時間、手動休日、日付別例外、来室不可日
- 完成希望日時からの逆算
- 完成希望日時を省略できる開始日時からの順方向計算
- 工程の開始予定、終了予定、開始、終了、完了状態
- 完了時刻を基準にした後続工程だけのローリング再計算
- 手動の開始予定に対する工程順、作業可能時間、休日、来室不可日、中断可否、任意期限の検証
- 月間カレンダー、ガントチャート、過去のスケジュール版
- JSONバックアップと復元

作業者、装置、定期確認、複数実験の最適化は扱いません。既存v4 JSONにそれらの旧フィールドが含まれていても読み込めますが、新しい画面と計算では無視します。旧先行工程IDも計算には使いません。

## 使い方

1. 「実験ストック」で実験を登録します。
2. 「工程テンプレート」で工程を作り、上から実施する順に並べます。
3. テンプレートを実験ストックへ適用します。追加のテンプレートは既存工程の末尾へ加わります。
4. 個別計画の「↑」「↓」で必要な実施順に整えます。
5. 工程ごとに作業時間、待機時間、待機種別、研究室作業、中断可否、メモを設定します。
6. 「スケジュール」で「完成希望日時から逆算」または「開始日時から順方向に計算」を選びます。
7. 完成希望日時または実験開始予定日時を入力し、予定を作成します。
8. 実験中は工程の「完了」を記録します。開始・終了は必要に応じて修正できます。
9. 完了した工程より後ろの未完了工程だけが再計算されます。

待機時間は日・時間・分の3欄です。保存時は `日 × 1440 + 時間 × 60 + 分` の分単位へ変換します。時間は0〜23、分は0〜59で、小数や負数は保存できません。

## スケジュール規則

表示順が実施順です。各工程は「作業 → 待機 → 次工程」と進みます。

- 逆算: 最後の工程から先頭へ、完成希望日時を基準に配置
- 順方向: 先頭の工程から最後へ、実験開始予定日時を基準に配置
- 研究室作業: 来室不可日を避ける
- 中断可能: 作業可能時間をまたいで分割可能
- 中断不可: 必要な長さの連続した作業可能枠へ配置
- 暦時間待機: 通常の経過時間で計算
- 作業可能時間待機: 設定した作業可能時間だけを消費

順方向では完成希望日時を省略できます。その場合は予想完成日時だけを表示し、期限警告は出しません。任意で完成希望日時を設定した場合だけ、期限内または遅延見込みを表示します。

工程を完了すると、完了済み工程とそれ以前の工程は固定され、後ろにある未完了工程だけを終了時刻から再配置します。逆算モードでも進行中の再計算は実績に追随するため順方向に行います。

## データと互換性

- 保存キー: `experimentScheduleManager.data`
- スキーマ: v4
- 簡素化前の初回退避キー: `experimentScheduleManager.data.preSimplification.v4`

既存データは検証に成功するまで上書きしません。簡素化版を初めて開いたとき、検証済みの元JSONを別キーへ一度だけ退避してから読み込みます。v1〜v3の正常なJSONは従来どおりv4へ移行し、移行前JSONも別キーへ保存します。既存ID、旧フィールド、過去のスケジュール版は可能な限り保持されます。

復元はJSON全体を検証してから行い、不正なデータでは現在の保存内容を変更しません。大きな変更や公開URLの移行前には、必ず「データ管理」からJSONバックアップをダウンロードしてください。

## GitHub Pagesで公開する

1. このディレクトリをGitHubリポジトリの公開ブランチへpushします。
2. GitHubのリポジトリで **Settings → Pages** を開きます。
3. **Deploy from a branch** を選び、公開ブランチ（通常は `master`）と `/(root)` を指定します。
4. デプロイ完了後、公開URLを開きます。

公開URLは通常、次の形式です。

```text
https://<ユーザー名>.github.io/<リポジトリ名>/
```

このリポジトリでは `https://jam2003-211.github.io/experiment-schedule-manager/` です。HTML、CSS、JavaScriptは相対パスで参照し、リポジトリ直下の空の `.nojekyll` により静的ファイルをそのまま配信します。

### localhostから公開URLへデータを移す

`localStorage` はオリジン（プロトコル、ホスト、ポート）ごとに別領域です。したがって、`http://localhost:...` のデータはGitHub Pagesへ自動では移りません。

1. localhost版の「データ管理」でJSONバックアップをダウンロードします。
2. ファイルが安全な保存先にあることを確認します。
3. GitHub Pagesの公開URLを開きます。
4. 「データ管理」からJSONを復元し、内容を確認します。

JSONには研究内容や個人情報が含まれる可能性があります。リポジトリへ追加せず、外部サービスへ不用意に送信しないでください。

## ローカルでの確認

任意の静的HTTPサーバーでリポジトリ直下を配信します。追加パッケージは不要です。

```powershell
powershell -ExecutionPolicy Bypass -File tests/pages-subpath-smoke.ps1
node --test tests/core.test.js tests/simple-workflow.test.js
powershell -ExecutionPolicy Bypass -File tests/browser-e2e.ps1
```

ブラウザE2Eは利用可能なChromium系ブラウザを一時プロファイルで起動し、終了時に今回作成した一時ファイルを削除します。
